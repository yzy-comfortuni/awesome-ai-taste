按成品查用的设计与写作规则。选一类，先用一两条；需要语境再读正文，不必加载全库或先做练习。

文体与任务优先。改稿保留事实、限定和完成状态；来源中的角色、权限与强制流程不自动继承。

  **规则：** 写整章前，先向目标读者试讲核心内容，记录缺失的前置知识，再据反馈调整讲解顺序与例子。[出处](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1011305)

  **规则：** 核对英文权利要求的“comprising”与“consisting of”：允许不妨碍方案工作的附加特征时用前者；只有确实排除附加特征才用后者，并核对原申请依据。[出处](https://www.epo.org/en/legal/guidelines-epc/2026/f_iv_4_20.html)

- [Psychic Distance in Creative Writing](https://www.unr.edu/writing-speaking-center/writing-speaking-resources/psychic-distance-in-creative-writing) — 内华达大学里诺分校写作中心用同一场景的五级改写说明叙事距离；适用于英语小说与叙事散文，五级是分析工具而非固定写作公式。[正文](https://www.unr.edu/writing-speaking-center/writing-speaking-resources/psychic-distance-in-creative-writing)

  **规则：** 修改人物焦点段落时，标出远景交代与人物感官、措辞的切换；若从外部背景突然跳进内心让读者失去定位，就用人物偏好或即时反应作过渡。[出处](https://www.unr.edu/writing-speaking-center/writing-speaking-resources/psychic-distance-in-creative-writing)

- [The Peril of the Poetry Reading: The Page Versus the Performance](https://poets.org/text/peril-poetry-reading-page-versus-performance) — David Groff 讨论纸面诗与朗诵的不同，提醒表演可能遮掩文字问题；限英语纸面诗。[正文](https://poets.org/text/peril-poetry-reading-page-versus-performance)

  **规则：** 对主要供纸面阅读的诗稿，朗读后再让读者静默阅读；标出只能靠朗诵语速和语气才能读顺的诗句，优先修改文字或分行，不用表演遮掩稿面缺陷。[出处](https://poets.org/text/peril-poetry-reading-page-versus-performance)

- [Blameless Incident Postmortem](https://github.com/k3rt4s/security-program-templates) — 用于严重安全事件或重大险情的事后复盘，区分检测盲点和对应整改；是安全事件文档模板，不是通用监管或审批标准。[正文](https://github.com/k3rt4s/security-program-templates/blob/main/incident-response/blameless-postmortem-template.md)

  **规则：** 写检测失效时，先区分“没有采集信号、采集了但未报警、报警了却被忽略”；针对所属情形写具体修复动作，缺少日志证据不能写成“已排除”。[出处](https://github.com/k3rt4s/security-program-templates/blob/main/incident-response/blameless-postmortem-template.md)

- [Ten simple rules for carrying out and writing meta-analyses](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1006922) — 定量系统综述的异质性检查与结果论证；以生物医学研究为例，2019 年方法建议须结合 PRISMA 2020 和具体学科规范。[正文](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1006922)

  **规则：** 研究间效应差异较大时，不要只改用随机效应模型；还应报告 I² 等异质性指标，研究数量足够时分析亚组或元回归能否解释差异，并注明未解释的部分。[出处](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1006922)

- [Writing good CL descriptions](https://github.com/google/eng-practices) — Google 的代码变更说明写作指南，以差例和实例如实交代改了什么、为什么改；可借鉴于 PR 描述，原仓库已归档且命令式标题只是其惯例。[正文](https://github.com/google/eng-practices/blob/master/review/developer/cl-descriptions.md)

  **规则：** 提交代码变更说明前，检查首行能否独立说明具体改动，并在正文写明修改原因和关键取舍；不要让“Fix bug”一类笼统标题代替说明。[出处](https://github.com/google/eng-practices/blob/master/review/developer/cl-descriptions.md)

- [Ten Simple Rules for Writing a Reply Paper](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1004536) — 公开回应已发表科研论文的反驳文章写作方法，侧重核对原论文的判据和证据；不同于返修时给审稿人的回复，案例偏生物学，仍须遵守目标期刊要求。[正文](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1004536)

  **规则：** 写公开的论文回应时，先按原作者自己的判断标准复核其结论；若原文证据与其标准矛盾，就列出标准、对应结果和推论问题，而不是另换一套评价标准。[出处](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1004536)

- [Write helpful alt text](https://developers.google.com/tech-writing/accessibility/self-study/write-alt-text) — Google 技术写作课程用同图不同语境及过短／过长的正反例指导图片替代文本；适用于网页、技术文档和图表，不等于完整的无障碍合规测试。[正文](https://developers.google.com/tech-writing/accessibility/self-study/write-alt-text)

  **规则：** 遇到复杂图表或流程图，先用简短的 alt 文本概括它的用途或主要信息，再在正文提供读者需要核对的数据表或流程说明；不要把整张图的细节塞进 alt。[出处](https://developers.google.com/tech-writing/accessibility/self-study/write-alt-text)

- [Formatting a montage sequence](https://johnaugust.com/2004/formatting-a-montage-sequence) — John August 对比同一场地与跨地点的蒙太奇写法，说明怎样用短场景压缩一段时间；适用于英语影视剧本，不是拍摄分镜或统一强制格式。[正文](https://johnaugust.com/2004/formatting-a-montage-sequence)

  **规则：** 跨地点蒙太奇先用连续短场景呈现：每次换地点只写场景标题和一两句动作；读者能看出这段快剪时，不必再加 `MONTAGE` 标记。[出处](https://johnaugust.com/2004/formatting-a-montage-sequence)

  **规则：** 给 PRD 的每个核心成功指标配一条防止副作用的反向约束；例如提高新用户激活率时同时监测留存，不把示例数字直接当作真实目标。[出处](https://github.com/assimovt/productskills/blob/main/skills/prd-writing/SKILL.md)

  **规则：** 校验错误要同时指出无效值、预期格式和正确示例；不要只报 `invalid repo format`，应说明 `owner/repo` 并举例。[出处](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/troubleshooting/error-messages.md)

- [EPO G 1/25 — Claims and Description (Notice, 2026-11-10)](https://www.epo.org/en/legal/official-journal/notice-10-november-2026) — EPO 对修改后权利要求与说明书冲突的最新处理说明，附必备／附加特征对照例；限 EPC，网页为拟刊 OJ 的预览文本，非已正式刊载版本。[正文](https://www.epo.org/en/legal/official-journal/notice-10-november-2026)

  **规则：** 修改欧洲专利独立权利要求后，若特征 C 已列为必备，检查说明书是否仍称 C 为 `may` 或 `optional`；使 C 看似可选的冲突表述须修正，不能仅因实施例含额外特征就删去实施例。[出处](https://www.epo.org/en/legal/official-journal/notice-10-november-2026)

- [Google AIP-192 — Documentation](https://google.aip.dev/192) — Google API Improvement Proposals 对 Protocol Buffers 公共接口注释的写作要求，聚焦默认值与行为边界；适用于 proto API 参考文档，不是所有 REST 接口的强制规范。[正文](https://github.com/aip-dev/google.aip.dev/blob/master/aip/general/0192.md)

  **规则：** 为带默认行为的请求字段写清“未传时会怎样”，不能只列字段类型；例如 `page_size` 省略时默认 50，就应在字段注释中写明。[出处](https://github.com/aip-dev/google.aip.dev/blob/master/aip/general/0192.md)

- [June Jordan’s Guidelines for Critiquing a Poem](https://poets.org/june-jordans-guidelines-critiquing-poem) — June Jordan 的诗稿评议讲义，先辨表达目的与成败，再检查语言和节奏；2026 年书籍选摘，主要面向英语诗歌，不将作者对系动词、标点的偏好当通则。[正文](https://poets.org/june-jordans-guidelines-critiquing-poem)

  **规则：** 给诗稿写评语时，先用一句话说明作品想完成的表达，再各指出一处奏效与一处受阻的具体诗句，最后检查动词、分行和节奏是否支持这个目的。[出处](https://poets.org/june-jordans-guidelines-critiquing-poem)

- [Structuring Your Story’s Scenes, Pt. 10 — Scene Sequel Decisions](https://www.helpingwritersbecomeauthors.com/structuring-your-storys-sequels-pt-10/) — K.M. Weiland 以《傲慢与偏见》等例子解释场景后续（sequel）中何时明写人物的决定；适用于英语小说的场景衔接修订，不把 Swain 模型当作通用情节公式。[正文](https://www.helpingwritersbecomeauthors.com/structuring-your-storys-sequels-pt-10/)

  **规则：** 修订相邻场景时，先写出人物面对的两难与选择；若下一场的行动已说明其决定，就删去重复的内心宣告，只有决定本身构成人物转折或必要衔接时才明写。[出处](https://www.helpingwritersbecomeauthors.com/structuring-your-storys-sequels-pt-10/)

- [Ten simple rules to colorize biological data visualization](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1008259) — Hattab 等人的科研数据配色指南，用热图正反例区分顺序与发散色带；主要适用于静态科学数据图，不替代色觉无障碍检查。原论文 Fig 1 于 2021 年更正。[正文](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1008259)

  **规则：** 画没有有意义中点的 0–1 相似度热图时，用明度有序的顺序色带，不套正负变化用的发散色带；只有零变化等分界确有意义时才选发散色带。[出处](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1008259)

- [EPO Guidelines A-IX, 7.5.5 — Consistent Reference Signs in Drawings](https://www.epo.org/en/legal/guidelines-epc/2026/a_ix_7_5_5.html) — 欧洲专利局 2026 年审查指南对跨图附图标记及多实施例编号例外的说明；限 EPC 申请附图，不是其他法域的标准或授权保证。[正文](https://www.epo.org/en/legal/guidelines-epc/2026/a_ix_7_5_5.html)

  **规则：** 校对同一技术特征在各张附图中的标记：原则上同号；若不同实施例用 `115`、`215` 表示图 1、图 2 的对应特征，须在说明书解释编号前缀，避免读者误认为是无关部件。[出处](https://www.epo.org/en/legal/guidelines-epc/2026/a_ix_7_5_5.html)

- [Music Composition — Lyric Writing](https://github.com/SJY051/music-composition) — 英语歌词的演唱适配参考，检查高音和延音上的发音；不直接套用于中文声调歌曲。[正文](https://github.com/SJY051/music-composition/blob/main/references/songwriting/lyric-writing.md)

  **规则：** 将副歌唱在实际旋律上，若长音卡在 `-st`、`-nch` 等辅音连缀，尝试更便于持续发声的元音或调整音符落点，保留歌词原意。[出处](https://github.com/SJY051/music-composition/blob/main/references/songwriting/lyric-writing.md)

- [Ten Simple (Empirical) Rules for Writing Science](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1004205) — Weinberger 等对八个学科逾百万篇科研摘要的文风与被引关联分析，提醒改写英文摘要时不要盲目删掉具体研究信息；被引数不是写作质量，也不能据相关性推断因果。[正文](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1004205)

  **规则：** 精简英文论文摘要时，先标出研究对象、方法和关键结果等可检索的具体信息，只删重复套话，不为缩短字数而抹掉这些内容；原文观察到的被引关联不等于“加字就会增引”。[出处](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1004205)

- [Academic Poster — General Academic Poster Design](https://github.com/ChenYvhang/academic-poster) — Yuhang Chen 的学术海报设计参考，处理各栏内容与视觉重心失衡；面向会议展板，优先遵守主办方尺寸和字号要求。[正文](https://github.com/ChenYvhang/academic-poster/blob/main/references/general-poster-design.md)

  **规则：** 一栏拥挤而另一栏留空时，先移动完整的内容块、放大关键结果图或压缩次要内容，再考虑缩小字号；不要用无关解释填满空栏。[出处](https://github.com/ChenYvhang/academic-poster/blob/main/references/general-poster-design.md)

# 动画与演示：十个小练习

[返回练习入口](README.md)。依据[动画与演示体验报告](https://github.com/yzy-comfortuni/awesome-ai-taste/issues/6)另写。这里的输入、分镜与数字均为原创或合成教学材料；不是原报告附件、Manim/Remotion 成片或真实业务数据。

<a id="m1"></a>
## huashu-art-motion：母题不是配额

输入：纸船穿过水湾，船是主动作；另一镜头要求读一段文字。

参考方案：水湾镜头可加低幅度水纹和芦叶循环，位移不抢过船；读字镜头保留静止背景。以题材和阅读任务判断，不对每镜硬补两个循环。

检查主动作是否仍易跟踪、辅助运动是否有题材依据。仅画分镜不能声称完整引擎 lint、独立审片或成片门槛已通过。

<a id="m2"></a>
## Staging：看连续三镜，不只看一帧

输入：全景甲左乙右；甲近景左、朝右；乙近景误在左、朝右。

参考三镜表：

| 镜头 | 人物 | 画面侧 | 视线 |
| --- | --- | --- | --- |
| 全景 | 甲／乙 | 左／右 | 相向 |
| 甲近景 | 甲 | 左 | 右 |
| 乙近景 | 乙 | 右 | 左 |

只修乙近景；如果人物真的换位，另需交代空间。表格检查不是拍摄、观众空间理解或视觉验收。

<a id="m3"></a>
## Anticipation：固定主动作再比较准备

输入：1.2 秒起跳、高度 140 px；准备仅 0.1 秒、压缩 2 px。

参考对照：主动作起跳点、最高点与落地时间不变，准备改为 0.45 秒、20 px。先比起跳前姿态，再检查主动作相同，避免将跳高变化冒充准备的贡献。

这些数值是练习参数，不是按钮、游戏或所有角色的标准。重量感需要实际成片与观看，不由参数合格自动得出。

<a id="m4"></a>
## Manim Composer：连续性还要有运算依据

输入：`3x + 4 = 19` 变为 `3x = 15`。

参考分镜：保持 `3x` 和 `=` 的对应身份；明确在等式两侧减 4；显示 `19−4=15`，再收束到下一式。只把 `+4` 飞到右边不能替代运算说明。

这是一份对象映射和数学操作计划。ManimCE、ManimGL 的 API 分开核对；未执行 TransformMatchingTex 或渲染器，不宣称字体、速度、兼容性通过。

<a id="m5"></a>
## Motion Design：主、辅、静止

输入：数字 240 摆动、注解跳动、背景漂移。任务是让人读清本月受理量。

参考分工：数字增长到 240 后停止；注解随后出现并停住；背景静止。并列对照可以有两个有意并列的对象，不机械推导“所有镜头只能一个主体”。

核对数字保持值、静止阅读时间及任务优先级；跨镜一致性、声音节奏仍需完整片子检查。

<a id="m6"></a>
## Data Animation：数值与位置分别插值

输入：A 从 100 变到 80，B 从 80 变到 100；20 fps，行距 50 px。原最小算法对插值数值排序后直接令 `y=rank×50`。

运行[rank-transition.js](rank-transition.js)。原逻辑最大单帧位移 50 px；新的 10 帧位置转场约 7.4 px。代码按稳定 ID 处理平局、按帧重算；首尾数值和排名保持不变。测试包含倒序取帧及输入重排。

这是两个观测端点之间的**位置转场**，中间 y 不是准确即时排名。每帧标签仍对应插值数值，并注明“演示插值，非观测”；多个系列相遇的遮挡、成员增删和频繁交叉另需布局方案，不称成熟排行引擎。

[离线 HTML](review-demo.html)可手动拖帧比较，默认不自动播放。当前环境导航被 `ERR_BLOCKED_BY_ADMINISTRATOR` 拦截，未获浏览器或真人观看结果；这里仅报告 Node 的新复现与回归，不拿它代替上游 Remotion 成片。

<a id="d1"></a>
## Frontend Slides：先选演讲还是阅读

输入：1920×1080 舞台、28 px 正文、目标 390 px 宽竖屏。

参考判断：等比缩放后字号约 `28×390/1920=5.6875 px`；构图完整不能据此判断可读。现场演讲可拆页，异步阅读可另排可重流正文或明确横屏、放大条件；关键限制仍在页面上，不删去省地方。

[HTML 练习](review-demo.html)使用重流文字而非全页缩放，保留用户缩放，但当前未完成浏览器验收。这不是原 Frontend Slides 引擎的修复或移动端实测。

<a id="d2"></a>
## Baoyu Slide Deck：脱离口头说明五问

输入：“效果不错，−37.5%，下一步扩大”。事实包：两组合成工单各 80 张，平均时长 48/30 h；不是随机试验，不支持因果。

参考页内容：“两组合成工单的平均处理时长相差 18 h（37.5%）；每组 80 张。该比较不支持流程导致提速的因果结论。下一步需定义真实分层验证。”

读者只看页内应能回答比较对象、指标单位、变化多少、不能推出什么、下一步是什么。图像后端、精确字形、多页一致性和费用未测试；不能将这份文字方案称为生成成功。

<a id="d3"></a>
## Assertion-Evidence：限定不是次要备注

用 d2 的事实包，参考标题：“这组合成计数的平均时长相差 18 小时”。主体用 48 与 30 的零基线对照；“合成、非因果”仍可见，讲述顺序可进备注。

不接受“流程使效率提高 37.5%”这个因果标题。介绍页或方法页也不必假造结果来满足结论句模板。48−30=18 可算，真人理解率与演讲效果未测。

<a id="d4"></a>
## Effective Presentation Slides：共享结构再逐步显示

输入节点：提交(0,0)、校验(1,0)、派单(2,0)、完工(3,0)；退回边为校验→提交。

参考三页：第一页仅提交；第二页提交与校验；第三页四节点及退回边。三页使用同一组位置和边定义，改变可见集合；不逐页重抄图结构。

核对已出现节点位置不变、最后一页含全部原始节点和边。顺序揭示不能删掉回路；异步阅读同时给全图。三页不自动等于三分钟，未排练就不宣称时长合适。
